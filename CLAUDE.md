# FASTLINE INFINITIQ — правила проекта

## Запреты

- **Папку `fastline-infinitiq/` НЕ ТРОГАТЬ** — пользовательская папка (добавлена юзером 2026-06-12). Не читать, не изменять, не удалять её содержимое без явной просьбы.
- **Папку `Prod/` НЕ ТРОГАТЬ** — пользовательская (та же договорённость).

## Стек и структура

- **С 2026-07-28: React 18 + Vite + react-router** (переписано с vanilla; старые файлы в `legacy/` — только справка, не редактировать). SEO через SSG-пререндер (`npm run build` → `dist/`), деплой GH Pages (`.github/workflows/deploy.yml`, **домен `fastlineinfinitiq.pl` с 2026-08-05**).
- **Прелоадер (2026-08-05):** инлайн в `index.html` (стиль+разметка+скрипт до бандла) — 3D-сетка на canvas, морф в спираль нейро-столпа на выходе; показывается только на `/`, API `window.__fiq.set/done` (сигналы из `Home.jsx`), страховка 4.2 с. Прячет подстановку CMS-контента. Лендинг ходит в Supabase чистым `fetch` (`src/lib/supabase-config.js`) — supabase-js только в lazy-чанках editor/login/audyt.
- CSS страниц извлечён **байт-в-байт** из legacy в `src/styles/*.css` и инжектится per-page `<style>` — не «улучшать» и не объединять.
- Движки (барабан/нейро-столп/курсор/редактор) — императивные модули в `src/engine/*`, вызываются из useEffect с cleanup. FIQ-модуль CMS: `src/engine/fiq.js`.
- **Секция «Mapa procesu» (v2, 2026-08-14):** демо-панель и все demo-симуляции из `landingEngine.js` УДАЛЕНЫ (`window.fiqInitServices` — no-op, Home.jsx его по-прежнему зовёт). Строка `_lists.svc` = карточка фазы: `{name, desc, foot, chips, demo, hidden}`; `name` рендерится как «первое слово = крупный титул + остальное = mono-подпись»; `chips` — сырой текст «Nazwa | opis; Nazwa | opis» (парсится в `FIQ.parseChips`); при пустых chips/foot берутся дефолты `FIQ.SVC_DEFAULTS` по ключу `demo` (strategy/gen/voice/llm/auto). Зелёный луч — чистый CSS `.svc-beam` (18s, стаггер по `--i`). **Секция `#dla-kogo` = «Co robimy» (WHO v2)**: первый элемент `_lists.who` — hero-карточка ({tag,h,p,cta,s1l,s1v,s2l,s2v}), остальные — категории ({tag,h,p}); спарклайн pipeline в hero рисует движок (`sparkTick`), ховер карточек даёт импульс. Матовые карточки (what/svc/who): внутри 3D-барабана `backdrop-filter` НЕ сэмплит канвас за гранью (Chromium) — **настоящий фрост рисует движок**: `.frost-c`-канвас в каждой карточке + downscale-каскад региона `#neural` (frostRects ДО записей барабана, frostDraw ПОСЛЕ drawNeural); база почти непрозрачная `rgba(16,17,13,0.9)`, иначе резкие точки двоятся с блюром. CSS-blur оставлен — работает в mode-flat.
- **Порядок граней (2026-09-07):** `start → audyt → czym-jestesmy → oferta → zespol (скрыт) → model → dla-kogo → grupa → kontakt`. Форма бесплатного аудита живёт в **отдельной грани `#audyt` вторым экраном** (`.aud-grid`: слева объяснение «что это и что клиент получит» + 4 пункта, справа `AuditForm`; на ≤1100px порядок опис → форма → пункты через `order`). Финальная грань `#kontakt` = CTA «Umów briefing» (`cta_btn`) + футер, формы там больше нет. Нумерация лейблов по видимым секциям: 01 audyt · 02 what · 03 svc · 04 model · 05 who · 06 kontakt; скрытая `#zespol` намеренно без номера (включишь — перенумеруй). Hero-кнопки: primary `data-goto="1"` → аудит, ghost `data-goto="2"` → «Czym jesteśmy». CSS-блок «AUDYT — sekcja 01» одинаков в `landing.css` и `editor.css`.
- **Hero v4 «kula z czterema wycinkami» (2026-09-07):** первая грань — оффер продуктов: крупный H1 в 2 строки, лид, по центру сфера из 2600 точек, **разрезанная крест-накрест на 4 сегмента = 4 группы** (табов нет). Движок **`src/engine/heroSphere.js`** (canvas 2D, своя 3D-проекция). Квадранты: `QUAD` — единственное место, где задано, какая группа в каком углу (сейчас c — право-верх, d — право-низ, a — лево-низ, b — лево-верх); `groupAt()` и `ORDER` выводятся из неё, менять раскладку — только там. **Выбор группы**: наведение на сегмент, на название группы или на карточку; внутри сцены ничего не сбрасывается (иначе путь «шар → карточка» гасил продукты), сворачивается только при уходе курсора со сцены. Карточки появляются последовательно (класс `.ready` по таймеру `reveal`), линий к продуктам нет — остались только выноски от названий групп к шару. Названия групп (`.pl-gname`; с 2026-09-08 берутся из `audit_catalog.group_name`, не из CMS) — Space Grotesk 700 на подложке с толстой acid-рамкой; неактивные втягиваются внутрь шара, активное встаёт над колонкой и выравнивается по её краю (ширину мерить только без transition на `font-size`). По кругу — 4 однонаправленные стрелки из точек с бегущей волной свечения. Простой 15 с → автопоказ групп каждые ~14 с, но не запускается, пока курсор держит группу; любое движение/клавиша/скролл прерывает. Плотность карточек `normal → dense → tight → micro → nano` подбирается по фактической высоте (описание не прячется, режется `line-clamp`), номера продуктов скрыты (`.pl-num`), медиазапросы `max-height: 820/720px` отдают сцене место заголовка. Режим списка — при `W < 560 || H < 260`: тап по сегменту открывает группу, повторный закрывает. **Скорость показа карточек (2026-09-09, ×3):** `reveal` = `dt/500` (было 1500), задержки `--d` 30 мс на карточку (в списке 24, было 90/70), CSS `.pl-node { transition-duration: 0.12s }` (было 0.26) — от наведения до полностью видимой группы ~0.65 с вместо ~1.9 с. ⚠️ `#start .pl-stage` не должен иметь `min-height` в `vh` — в гриде это распирает строку и сцена наезжает на кнопку.

- ⚠️ **`html.mode-flat` ≠ «редактор» на страницах продуктов:** движок `agenciEngine` вешает `mode-flat` и на обычном мобильном виде (≤1000px), поэтому редакторские правила (скрыть канвас силуэтов, раскрыть все шаги демо) обязаны висеть на **`body.fiq-edit`**. На лендинге разницы нет (там всегда `mode-3d`), поэтому старые правила `html.mode-flat` в `editor.css` остались.
- **Телефон = плоский режим (2026-09-10):** на ≤900px и на тач-устройствах лендинг и продуктовая страница включают `mode-flat` — барабана и 3D-трансформаций нет, обычная прокрутка; frost-канвасы не рисуются вовсе (`frostRects`/`frostDraw` выходят сразу). Замер при CPU ×4: 60 fps на обеих страницах. `html { overflow-x: clip }` на ≤900px — при первой раскладке карточек в куле `scrollWidth` документа успевал стать шире экрана.
- **Подписи групп в куле стоят в «окнах» между дугами (2026-09-10):** дуги-стрелки идут по осям (верх/право/низ/лево, ±0.5 рад), значит свободны диагонали — подпись ставится так, чтобы её ближний к центру угол лежал на `R*1.2 + 16` (на телефоне +8), весь прямоугольник снаружи кольца. **Дуги рисуются и на телефоне**; чтобы подписи там помещались, в режиме `list` сфера меньше (`R = min(W*0.27, 104)`, `cy = R*1.35 + 22`), а сами подписи переносятся на две строки (`white-space: normal; max-width: 104px; font-size: 11px`). Стрелка вниз стартует ниже подписей (`cy + R*1.2 + 52`). Проверка — `labchk.js` (точки дуг против прямоугольников подписей на 1920/1440/390).
- **Мобильная куля — доводка (2026-09-10):** радиус в режиме `list` уменьшен (`min(W*0.32, 124)`), центр опущен до `R*1.42 + 12` — иначе верхняя дуга стрелок вокруг сферы срезалась краем канваса; под сферу отдано `padding-top: 372px` у `.pl-nodes`, чтобы стрелка вниз не упиралась в карточки. Карточки въезжают снизу (`translateY(16px)` + стаггер `--d`; **`!important` обязателен** — старое правило списка обнуляет transform тем же словом). Acid-кромка карточки прижата к `left: 0`, текст отодвинут `padding-left: 18px` (раньше линия шла по буквам). **Выбор группы на телефоне скроллит к карточкам** (`scrollToCards()` в heroSphere).

## Правила кода (уроки HORIN)

- `prefers-reduced-motion` игнорируется сознательно (Windows-кейс) — не возвращать.
- DOM-стили писать только при реальном изменении значения (не каждый кадр).
- JS не пишет transform элементам, чей transform управляется media query.
- **Enter в редакторе:** в полях без `data-edit-type="html"` Enter завершает правку (blur) — если тексту нужен перенос строки, поле обязано быть html-типа. В html-полях Enter вставляет `<br>` (`insertLineBreak`), а не браузерный `<div>` — иначе в CMS попадают лишние блоки и едут отступы.
- Классы шторки перехода — `w-in`/`w-out` (не `in`/`out` — конфликт с entrance-анимацией контента на kontakt).
- После правок прогонять puppeteer-проверку: 1440×900 + 390×844, 0 console errors, 0 переполнений. Скрипты в `/tmp/pptr-fiq/` (puppeteer-core + Chrome из `~/.cache/puppeteer`). **Не использовать `clip` + `deviceScaleFactor: 2`** — отдаёт чёрные клипы; делать полные скриншоты. `page.waitForFunction` в headless задавать `{ polling: 300 }` — дефолтный rAF в фоновой вкладке не тикает и ожидание виснет до таймаута. Детектор переполнений обязан пропускать элементы неактивных граней барабана: 3D-проекция искажает их `getBoundingClientRect`, а `#stage` их и так обрезает.

- **Реестр продуктов платформы `fiq_products` (2026-09-08):** зонтик `brain` = «Agenci AI» разделён на два продукта — **`advisor`** («AI Doradca») и **`sales`** («AI Sprzedawca»), оба в домене `brain.fastlineinfinitiq.pl` (AI Asystent добавим, когда будет модуль). Панель фильтрует меню/роуты/вкладки/интеграции по `session.product.key`, админ видит всё; ключи домена — в `Prod/brain.fastlineinfinitiq/src/lib/products.js`.
